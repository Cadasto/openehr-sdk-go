# Plan — SDD documentation sweep

**Date:** 2026-11-16
**Status:** Draft. The audit is done; waiting for the maintainer's rulings below before any edit. This file is deleted when the sweep merges.
**Covers:** every file under `docs/specifications/`, `docs/adr/`, `docs/plans/`, and the process documents (`AGENTS.md`, `docs/development-process.md`, `docs/ai-workflow.md`, `docs/roadmap.md`, `docs/architecture.md`).
**Defers:** code removals (deprecated `ValidateRMEHRStatusBytes`, `(*Document).Tree`, `WithRelaxedTypeDispatch`, the v0.28.0 legacy XML spelling); `openehr/serialize/simplified/deviations.md` (112 KB, not audited).

## Goal

Make the SDD layer lighter for agents without dropping a rule a caller relies on: fewer bytes per requirement excerpt, one home per rule, no history in normative text, honest statuses, and `MUST` only where §4 of the methodology puts it.

## What the audit found (main at 5de60951)

| | Now | After (estimate) |
|---|---|---|
| `MUST`s in the specs | ~952 | ~830 |
| Spec bytes | ~1,140 KB | ~880 KB |
| ADR bytes | 288 KB | ~205 KB |
| Process docs an agent reads | ~231 KB | ~88 KB (+ ~70 KB moved to tool docs and the knowledge base) |
| Reading before a bug fix (targeted) | ~66 KB | ~26 KB |
| Largest REQ excerpt (REQ-107) | 81 KB | ~35-55 KB |

Over-used `MUST` is a smaller problem than it looks: after the October pass most `MUST`s bind caller-visible behaviour. The weight is in structure (rules not addressable by heading, sections stranded outside their REQ excerpt), rules stated in two to eight places, dated history and vendor evidence inside normative text, and stale facts. Merging requirement ids rarely pays: tests cite them in their names (REQ-107 alone has ~1,380 citations), so only one small merge is proposed.

## Phases

One branch (`docs/sdd-sweep`), one commit or a few per phase, `make spec-check` after each. Phases go from no judgement to judgement, so a review can stop at any boundary; the branch can be cut into stacked PRs there if the diff is too big.

### Phase 0 — Fix what is wrong

Stale or contradicting facts only; no rule changes. ADR stale targets and facts (0007, 0008, 0011, 0013, 0034:44, `codegen-verify`); `roadmap.md:59`; PROBE-002's `spec_version` clause and PROBE-040's mapping; `auth.md:121, :766, :807`; `wire.md:35`; `reference-model.md:325, :362, :537`; `make spec-gen` references; the plans-are-gated claim (`plans/README.md:7`, `development-process.md:39`); the `REQ.md` reservation clause; `ai-workflow.md:7`; `architecture.md:113` OTel scope; `adr/README.md:54`; add the ADR index to `make spec-generate`.

### Phase 1 — Structure, no wording change

Re-level `wire.md`'s stranded sections (Floating-point precision, Polymorphic substitution, AQL executor) under their REQ. Turn run-in bold labels and paragraph-sized table rows into `####` headings so `RULE=` reaches them (REQ-102 dimensions, REQ-112 catalogue, REQ-161 codes, `wire.md` labels). Create `aql.md` if ruling 1 says so. Anchors are kept or every inbound link re-pointed.

### Phase 2 — One home, no history

Informative text only, no keyword moves. Per the ledger: second homes collapse to pointers; dated logs, PR memoirs, acceptance gates and vendor evidence leave the specs and ADRs; conformance Status lines become the status token plus one clause (keep the shapes `probe-status.sh` and `TestREQ082ProbeClassMatchesModes` read); resolved strands shrink to one line under their heading; process docs keep one home per rule; `development-process.md`'s probe harness, CDR tool and fixtures sections move to tool docs; plans per ruling 4; `make spec-context` guidance puts `OUTLINE=1` first.

### Phase 3 — Keyword force

The ledger's demotions and collapses (~120 `MUST`s), each auditor's keep-list respected. Contract gaps close in the same phase: the ADR 0004 quoted-number tolerance gets its spec rule in REQ-052, the `AUDIT_DETAILS` default is keyed as a departure, `clinical-modeling.md:500` is bolded.

**Safeguard (lesson of PR 318, where workers over-demoted):** a demotion ledger in the findings file lists every removed or collapsed keyword with the base sentence, the new sentence and the reason; it is checked against the base copy before review, and no collapse may widen a rule.

### Phase 4 — Requirement ledger

Status flips (ruling 3), REQ-143 into REQ-177 (ruling 5), REQ-114/115 released, orphan Draft probes (PROBE-032, 050, 063, 064, 068) marked Deferred with a Satisfies line or retired, STRAND-04 closed by ADR 0022, ~56 test citations of retired REQs re-cited to their survivors, `make spec-generate`.

### Phase 5 — Verify

`make spec-check`, `make sdd-check` (warnings down from 7), `make docs-check`, `go test ./testkit/... ./cmd/examples/...`, then `make ci`. An `/sdd-review` pass with the document reviewer plus the demotion-ledger check. PR body about 450 words.
