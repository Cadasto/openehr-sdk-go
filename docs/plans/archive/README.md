| [2026-08-18-path-segment-validation.md](2026-08-18-path-segment-validation.md) | Path-parameter segment validation — **[REQ-150](../../specifications/transport.md#req-150--path-parameter-segment-validation)** (`landed`, first allocation in the new transport extension band 150–159), **PROBE-091** Implemented (Sandbox). Made the transport the single path *validator* as well as the single encoder REQ-095 already made it: `ValidatePathSegment` / `ValidateRequestPath` refuse a segment that IS `.` or `..`, is empty, or carries `/`, `\`, a C0 control byte or DEL — while every percent-encodable octet still passes, so `Referral Request.v1` and `%2e%2e` are ordinary segments. Enforced at `Do`'s request-preparation site rather than inside `joinTarget`, whose call site already wraps `ErrInvalidConfig` (routing the validators' double-sentinel chain through it would wrap the sentinel twice). Splitting on `/` cannot see a separator smuggled INSIDE one parameter — those segments are individually legal — so a second rule refuses a path whose segment count contradicts its `Route` template. `Route` therefore gates the smuggling defence, and since it otherwise reads as an observability field, `openehr/client` gained an **AST** tripwire (not a grep: `ehr.go` assigns `req.Route` after the literal) holding every `transport.Request` literal to setting it. A `Path` of exactly `"/"` is the service root and passes — the landed System API's only operation is `OPTIONS /`. PROBE-091 drives ten leaf entry points with four hostile ids: two that change segment count and two that preserve it, so the two halves of REQ-150 are exercised independently — mutation testing showed the obvious pair alone let an arity-only implementation pass. **Deferred:** a breaking `PathSegment` named type on every leaf; validating the service base URL; `cadasto/admin`'s health-probe paths, which bypass `transport.Do` by design. Landed |
