## Context

The canonical-JSON codec is generated code. `internal/bmmgen/render_jsonmar.go` (451 lines) and `internal/bmmgen/render_jsonunmar.go` (473 lines) emit one `MarshalJSON` and one `UnmarshalJSON` per generated type; `openehr/rm` carries 110 of each and `openehr/aom/aom14` 29 of each, 14 509 generated lines in total. `openehr/internal/jsonpoly/jsonpoly.go` (80 lines) supplies `_type` for a value held in an interface, through 177 generated call sites. `openehr/serialize/canjson/marshal.go:28` is a thin pass-through over `encoding/json`.

Almost all of it exists to obtain three things `encoding/json` v1 does not give: a discriminator on a value held in an interface, `_type`-driven dispatch on decode, and a per-type funnel for the shape sentinel. Two of the three are v2 defaults. `go doc encoding/json` § Migrating to v2 states: "In v1, MarshalJSON methods declared on a pointer receiver are only called if the Go value is addressable. In contrast, in v2 a MarshalJSON method is always callable regardless of addressability." That single sentence retires `jsonpoly`. Decode dispatch is served by `json.UnmarshalFromFunc` registered through `json.WithUnmarshalers`, one hook per polymorphic interface: 21 hooks against 181 slot occurrences.

Go 1.27 ships `encoding/json/v2` and `encoding/json/jsontext` as ordinary standard library, with v1 reimplemented on v2 and its behaviour preserved. The module floor is already `go 1.27.0` (`go.mod:3`).

## Decision

**The canonical-JSON path is encoded and decoded by `encoding/json/v2`, and the generator emits the streaming marshaler pair instead of bespoke JSON codec methods.**

- **Design.** Per concrete class the generator emits a method-free alias type and two short methods: `MarshalJSONTo(*jsontext.Encoder) error` (`go doc encoding/json/v2.MarshalerTo`), which calls `json.MarshalEncode` on an anonymous struct whose first field is `_type` and whose second embeds the alias; and `UnmarshalJSONFrom(*jsontext.Decoder) error` (`go doc encoding/json/v2.UnmarshalerFrom`), which calls one shared runtime helper. A class that embeds a marshaler-bearing concrete ancestor cannot take that zero-copy alias, because a defined type over such a struct promotes the ancestor's streaming methods and would dispatch to the ancestor under the wrong `_type` with no compile error (ruling R19); the generator's `embedsMarshalerBearingConcrete` predicate routes those classes to a flat wire struct that embeds nothing and copies each field, so both shapes still lead with `_type`. Substitutable slots are served by one `json.UnmarshalFromFunc` per polymorphic interface, built from `typereg.Default` at init. `openehr/internal/jsonpoly` is deleted. The decoders are specified for a zero-value receiver: reuse of a populated receiver is unspecified and differs between the two shapes today: the alias path decodes in place (an absent member leaves the existing value), the flat path decodes into a fresh wire struct and assigns every field (an absent member resets to zero).
- **Scope.** Five packages move: `internal/bmmgen`, `openehr/rm` (generated plus the hand-written primitives), `openehr/aom/aom14`, `openehr/rm/typereg` and `openehr/serialize/canjson`. `openehr/internal/jsonpoly` is deleted. Everything else stays on `encoding/json` v1, which remains supported and is itself implemented on v2. The split is drawn where the canonical-JSON contract ends: every package that decodes an RM value moves together, so there is never more than one decode-error taxonomy behind the sentinels REQ-052 keeps distinct.
- **Determinism is an option, not an emergent property.** `go doc encoding/json/v2.Marshal` states that a Go map "is traversed in a non-deterministic order", and `go doc encoding/json/v2.MarshalerTo` tells a custom marshaler to "respect the Deterministic option". The generated marshalers set `json.Deterministic(true)`.
- **Cut-over, not a flag.** The generator emits one shape. Rollback is `git revert` plus `make codegen`, proven by `make codegen-verify`, which `make test` runs first (`Makefile:192`).

## Consequences

- **About 12 800 generated lines and one internal package go away.** 278 generated methods become roughly 1 700 generated lines plus 21 registered hooks, and `internal/bmmgen`'s two JSON templates shrink from 924 lines while keeping the same shape as each other.
- **Encoded bytes change, in four ways a consumer can see.** `jsontext.EscapeForHTML` is opt-in in v2 where v1 escaped `<`, `>` and `&` unconditionally, so a `TERM_MAPPING.match` carrying `<` now spells `"<"` on the wire where it spelled `"\u003c"`. [REQ-052](../specifications/wire.md#req-052)'s `TERM_MAPPING.match` bullet already puts that obligation on the decoded character rather than the literal bytes, so no contract breaks. Separately, pointer fields are tagged `omitzero`, not `omitempty`: under v2 `omitempty` omits a non-nil pointer to an empty string (it encodes as `""`), whereas `omitzero` omits only the nil pointer, so a pointer to `""` still emits `""` — the v1 spelling — and only an absent (nil) pointer is dropped. Container fields keep `omitempty`: under `omitzero` a non-nil empty slice is not zero and would emit `[]`, which [REQ-052](../specifications/wire.md#req-052)'s `DV_TEXT.mappings` re-encode collapse clause states outright would be RM-invalid (`Mappings_valid`). Third, an RM value held as a **map value** was unaddressable under v1 and so lost its `_type`; the value-receiver `MarshalJSONTo` (ruling R19) now emits one: a `Hash<String, RM_TYPE>` such as `AUTHORED_RESOURCE.translations` gains a `_type` on every entry, a correctness improvement rather than a break. Fourth, an interface-typed optional attribute holding a **typed-nil pointer** (`ELEMENT.value`, `ELEMENT.null_reason`, `LOCATABLE.uid` and the like) is now omitted where v1 spelled it `null`: v2's `omitempty` drops a member that would encode as `null`, v1's dropped only a nil interface. This matches how `rm.IsTypedNil`, `ValidateRM` and the simplified encoders already read such a value as absent, so it is the truer spelling. A v1 `encoding/json` caller still gets `null`, because the generated `MarshalJSONTo` inherits that caller's `OmitEmptyWithLegacySemantics` through `typereg.MarshalOptions`, just as it inherits v1's HTML escaping; byte parity between the two entry points is not a promise.
- **Decode is stricter in three ways.** Invalid UTF-8 and a lone surrogate escape are refused by `jsontext` rather than silently substituted with U+FFFD, which is what [REQ-052](../specifications/wire.md#req-052)'s `TERM_MAPPING.match` bullet asks for and moves the refusal out of `rm.Character` into the standard library. An object with duplicate member names is refused. Member names match case-sensitively on this path. A body that used to decode can now fail.
- **Encode is stricter too.** `canjson.Marshal` refuses a Go string holding invalid UTF-8 with `canjson.ErrInvalidValue`, where v1 wrote U+FFFD, and `canjson.MarshalIndent` refuses an indent or prefix that is not made only of spaces or tabs (ruling R23). Both are new encode-side refusals a caller can now hit.
- **Decode error types change identity.** `*json.SyntaxError` gives way to `*jsontext.SyntacticError`, and `*json.UnmarshalTypeError` and `*json.UnsupportedTypeError` to `*json.SemanticError`. The SDK's own sentinels are unchanged: `canjson.ErrInvalidShape`, `canjson.ErrInvalidValue`, `transport.ErrInvalidShape`, the `typereg.Err*` family and `*transport.DecodeError` keep their identity and their `errors.Is` and `errors.AsType` behaviour. A consumer matching on the SDK sentinels needs no change; one matching on the standard-library types does.
- **A typed error gains a value-bearing field.** `json.SemanticError` carries `JSONValue jsontext.Value`, the JSON number or string that could not be unmarshaled. That is inside the class [REQ-052](../specifications/wire.md#req-052) § Causes may name the literal already permits for a cause, and the value-free discipline binds only `WireError.Error()` and `DecodeError.Error()`, so no rule breaks. A consumer that logs a wrapped cause wholesale now reaches a payload value it could not reach before.
- **v2 supplies the diagnostic path the SDK hand-builds** (amended 2026-09-15, single-pass decode). `json.SemanticError.JSONPointer` is an RFC 6901 pointer computed by the decoder, where `openehr/rm/composition_jsonunmar_gen.go:117` builds `/content/0` by hand. `typereg.DecodeError` stays the public envelope and may read its `Path` from the pointer. One caveat: a nested decode inside a hook restarts the pointer at that slot's own root, so a hook that does not decode in place produces relative paths. The concrete decode reads `_type` from the declared wire field after one `json.UnmarshalDecode`, rather than buffering and peeking. Three edges follow. A body that is both a wrong whole-value `_type` and a shape failure now reports the shape failure (`ErrInvalidShape`), where the buffer-and-peek reported the `_type` mismatch (`ErrTypeMismatch` on `/_type`) first, because the discriminator is checked only after a successful decode; a positive test pins this precedence (ruling F8). And a shape failure inside a value reached without a polymorphic hook now carries a `JSONPointer` rooted at the enclosing object rather than at that value, a fuller path, which no normative sentence or test pins. And after the discriminator guard refuses a whole-value `_type` mismatch, the receiver holds the foreign body the decode already wrote for the alias shape, whose decode writes into the receiver directly through the type-converted embed (the flat wire-struct shape decodes into a local value and returns before its field copies, so its receiver stays untouched on that failure); either way the guard runs only on a completed decode, and the codec never promised to leave the receiver untouched on error.
- **One public constraint is affected.** `openehr/client/ehr/contribution/submission.go:51` declares `CommitVersion interface { json.Marshaler; BMMName() string }`. A type implementing only `MarshalJSONTo` satisfies `json.MarshalerTo`, not `json.Marshaler`, so the constraint moves or the generated types keep a thin `MarshalJSON` beside the streaming one.
- **`openehr/rm/typereg/nilreceiver_census_test.go` stops finding its subjects.** It enumerates `json.Unmarshaler` implementations at `:71` and `:93`. Under `UnmarshalerFrom` that census silently covers nothing, which is worse than failing. It is made interface-agnostic in the same change.
- **Amended 2026-09-24, PR 174:** the reviews of the single-pass concrete decode settled seven points. (a) Outside a buffered value the first failure in document order wins; inside a buffered value (`Registry.Decode`'s document, a polymorphic slot) and for a v1 caller, malformed bytes win. The rule is stated in [REQ-052](../specifications/wire.md#req-052) § Decode-side shape sentinel, malformed-JSON exclusion, and pinned by `TestUnmarshalFirstFailureInDocumentOrderWins`. (b) The depth bound is measured from the document root across polymorphic slots, where a buffered slot had restarted the count; how undeclared nesting is measured on each route is stated in [REQ-108](../specifications/clinical-modeling.md#req-108--untrusted-document-bounds) and pinned by `TestUnmarshalMaxDepthAcrossPolymorphicSlots` and `TestUnmarshalUndeclaredNestingDependsOnBuffering`. (c) Under v1 decode options a case-variant `_TYPE` member populates the declared `_type` field and is compared as the discriminator, so `{"_TYPE":"DV_CODED_TEXT"}` decoded into `DVText` now reports `ErrTypeMismatch` where the buffer-and-peek decoded it. (d) The receiver state after a `_type` mismatch, described above for the two shapes, is now pinned on both by `TestUnmarshalTypeMismatchLeavesReceiverAsDocumented`. (e) The SDK's two v1 `encoding/json` call sites on the RM decode path, `openehr/validation/rmfloor_bytes.go` and `openehr/client/demographic/versioned.go`, moved to `encoding/json/v2`. The move changes more than duplicate handling. v2 matches member names exactly, so a case-variant name is an unknown member: `ValidateRMEHRStatusBytes` reports `required` at `/name` for `"Name"`, and the demographic version read leaves the uid and the data empty when they are spelled `UID` and `Data`. A repeated member is refused at both sites, and the validator also reports `invalid_shape` for invalid UTF-8 inside an unknown member. Pinned by `TestValidateRMEHRStatusBytes_V2DecodeSemantics` and `TestGetVersionCaseVariantMemberIsUnknown`. (f) `DecodePolymorphic` now peeks a slot's `_type` under the caller's decoder options, where it used v2 defaults, so a bare v1 caller's options govern the whole decode, slots included. Before, a slot refused invalid UTF-8 with `canjson.ErrInvalidShape`, a malformed-input failure acquiring the shape sentinel against the malformed-JSON exclusion of [REQ-052](../specifications/wire.md#req-052), and refused a duplicate name that v1 accepts elsewhere in the same input. `canjson` callers and bare v2 callers with default options are unchanged; a bare v2 caller that sets its own options (for example `jsontext.AllowDuplicateNames(true)` or `json.MatchCaseInsensitiveNames(true)`) now gets them inside slots too, and `Registry.Decode` keeps v2 defaults. This is the slot counterpart of (c): under v1 options `{"_TYPE":"DV_CODED_TEXT"}` compares as the discriminator on a concrete `DVText` target and reports `ErrTypeMismatch`, but inside a slot it dispatches to `DV_CODED_TEXT`. The rule is stated in REQ-052's v1-caller paragraph and pinned by `TestBareV1CallerOptionsGovernPolymorphicSlots`. (g) A new sentinel, `typereg.ErrNilArgument`, classifies a nil argument: `DecodeInto` and `DecodePolymorphic` refuse a nil decoder and a nil target, and `DecodeInto` also a nil `gotType`, with a `DecodeError` wrapping the sentinel ([REQ-025](../specifications/idiom.md#errors-req-025)). Pinned by `TestDecodeIntoNilArguments` and `TestDecodePolymorphicNilArguments`.

## Alternatives considered

- **Keep `encoding/json` v1 and the generated marshalers.** Zero migration risk; every pinned behaviour stays pinned by construction. **Rejected:** it keeps 924 lines of generator template and 278 generated methods whose purpose is to reproduce what v2 gives directly, in the highest-churn part of the tree, since every BMM bump re-emits all of them. With the order promise withdrawn there is nothing left for them to buy.
- **Swap the codec but keep the v1 method pair (`MarshalJSON` / `UnmarshalJSON`).** Smaller diff, and it keeps `CommitVersion` and the nil-receiver census working unchanged. **Rejected:** it leaves all 278 methods in place and books a second migration to remove them, and it forgoes the allocation win the streaming pair exists for. `go doc encoding/json/v2.MarshalerTo` recommends it over `Marshaler` as "both more performant and more flexible". The two objections become tasks in the implementing plan.
- **Emit no methods at all and build the codec from registry-driven options.** Fewest generated lines in theory. **Rejected:** the behaviour would then exist only when the caller supplies the options, so `json.Marshal(&rm.DVText{...})` without them emits no `_type`. Today the generated methods make every RM value self-describing under any JSON entry point, and losing that is a public API regression.
- **`sonic`.** A JIT-assisted encoder with large throughput gains on x86-64. **Rejected:** a third-party dependency in the SDK's hottest correctness path, architecture-sensitive, and it addresses the performance axis while leaving every generated line in place. STRAND-04 keeps the two axes separate on purpose.
- **`easyjson`.** Generated marshalers, which the SDK already has in its own generator. **Rejected:** it replaces one code-generation surface with another and adds a dependency to do it.
- **A permanent split: migrate `openehr/rm` and leave `aom14` or the RM primitives on v1.** **Rejected:** [REQ-052](../specifications/wire.md#req-052) requires `openehr/aom/aom14` to classify decode failures "on the same terms as the canonical-JSON RM surface", and `transport.Decode` routes every 2xx body through `canjson.Unmarshal` (`transport/client.go:654`). A permanent split leaves two decode-error taxonomies behind one sentinel set. Phasing the work across commits is fine; shipping the split is not.
